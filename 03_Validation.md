# 03. Validation

The engine implements multiple independent validation methods. This
document describes each, what function(s) implement it, and why it
exists in the research process.

## Walk-Forward Validation

**Functions:** `compute_fold_boundaries`, `run_validate`,
`run_validate_dynamic`, `run_sweep`.

`compute_fold_boundaries` splits the available history into expanding-
window folds (a growing training window, a fixed-size out-of-sample test
window per fold), respecting a warmup period and minimum training/test
sizes. `run_validate`/`run_validate_dynamic` evaluate one fixed
configuration across all folds, plus BTC bull/bear regime stratification.
`run_sweep` grid-searches configuration parameters using a chronological
in-sample/out-of-sample split.

**Why it exists:** a single backtest window can produce a result that is
a lucky (or unlucky) property of that specific period. Walk-forward
validation tests whether a result holds across multiple, non-overlapping
time periods.

## Purged Validation

**Functions:** `run_purged_validation`, `purge_and_embargo_samples`.

Implements the Lopez de Prado purged walk-forward methodology: training
samples whose label window overlaps a fold's test period are removed
("purged") before fitting, since their outcome is not knowable using only
information available before the test period begins.

**Why it exists:** a label generated by looking `max_holding` days into
the future can leak information from inside the test period into the
training set if the sample's entry falls before the test period but its
resolution falls inside it. Purging removes exactly those samples.

## Embargo

**Function:** `purge_and_embargo_samples` (embargo component; embargo
length equals `max_holding`).

After each prior fold's test period, an embargo window is applied before
the next fold's training data resumes.

**Why it exists:** even after purging, samples immediately following a
test period can still be serially correlated with it. The embargo
enforces a clean gap between one fold's test period and the next fold's
training data.

## Bootstrap

**Functions:** `bootstrap_logreg`, `percentile`, `run_train_model`
(reports per-fold coefficients and bootstrap confidence intervals).

Refits a regularized logistic regression many times on resampled data to
estimate a coefficient's sampling distribution and confidence interval,
rather than reporting a single point estimate.

**Why it exists:** a single-fit coefficient gives no information about
how stable or noise-driven that estimate is. Bootstrap resampling
quantifies that uncertainty directly.

## Monte Carlo

**Functions:** `run_monte_carlo_robustness`, `compute_risk_of_ruin`,
`print_monte_carlo_report`.

Repeatedly resamples the realized trade set (bootstrap resampling with
replacement) and recomputes portfolio metrics (CAGR, Sharpe, Sortino,
Calmar, Max Drawdown, Profit Factor, minimum equity fraction reached) for
each resample, then reports the distribution.

**Why it exists:** answers "is the point-estimate baseline a robust
expectation, or a lucky ordering of a fixed set of trades." Reuses
`compute_portfolio_metrics()` unmodified; does not change any trade or
metric-computation logic, only the ordering/composition of the resampled
trade set.

## Permutation Testing

**Function:** `permutation_test`.

Tests whether an observed relationship between a feature/component and an
outcome metric (e.g., win rate) is stronger than what would occur by
random chance, by repeatedly shuffling the labels and recomputing the
metric.

**Why it exists:** correlation or a raw metric difference alone does not
establish statistical significance; permutation testing provides a
non-parametric significance estimate.

## Feature Attribution

**Functions:** `run_attribution`, `information_gain`, `phi_coefficient`,
`pearson_r`, `diagnose_component_timing`, `run_rs_lookback_sweep`.

Breaks the conviction score into its components and measures each
component's contribution via ablation (ON vs. forced-OFF trade-set
comparison), correlation plus permutation test, information gain, and
pairwise redundancy (phi coefficient) between components.

**Why it exists:** determines whether each individual scoring factor
adds real, independent information, or is redundant with another factor,
or contributes no measurable edge at all.

## Regime Testing

**Function:** BTC bull/bear stratification within `run_validate`/
`run_validate_dynamic` (via `trailing_return` against `btc_closes`).

Splits fold results by the prevailing BTC trend at the time, to check
whether performance is uniform across regimes or concentrated in one.

**Why it exists:** a strategy that only works in one market regime is a
materially different (and riskier) claim than one that is regime-robust.

## Portfolio Testing

**Functions:** `run_portfolio_report`, `run_risk_profile_comparison`,
`run_autonomous_portfolio_optimization`, `compute_portfolio_correlation`,
`print_correlation_report`.

Evaluates the pooled out-of-sample trade set at the portfolio level:
compounded equity curve, correlation structure across assets, and
comparison across the three named risk profiles (GROWTH, BALANCED,
CAPITAL_PRESERVATION).

**Why it exists:** trade-level statistics (win rate, expectancy) do not
by themselves determine portfolio-level survivability; concentration,
correlation, and drawdown behavior must be evaluated separately.

## Additional Read-Only Audits

- `run_data_audit`/`audit_csv_raw` -- raw CSV integrity (gaps,
  duplicates, missing fields, zero-volume/flat-price days, OHLC
  consistency, statistical outliers, wash-trading screening heuristic).
- `run_feature_warmup_audit`/`find_first_valid_index` -- per-asset,
  per-feature first-valid dates and effective sample sizes.
- `verify_causality` -- empirically verifies a feature's value at index i
  does not change if future data is altered, directly testing for
  look-ahead leakage.
- `verify_label_fidelity`/`run_label_audit` -- verifies diagnostic label
  tooling matches the real, unmodified `build_training_samples()` exactly,
  and reports label overlap/uniqueness (`compute_label_uniqueness`,
  average uniqueness per Lopez de Prado), class balance, holding-period
  distribution, and exit-reason distribution.
- `run_probability_diagnostic` -- out-of-sample probability calibration:
  ROC AUC (`roc_auc`), PR AUC (`pr_auc`), Brier score (`brier_score`),
  10-bin calibration curve (`calibration_curve`).
- `run_forward_return_audit` -- tests linear/monotonic information
  content of features against continuous 30-day forward return,
  independent of the triple-barrier label, with permutation significance
  and bootstrap confidence intervals.
- `run_nonlinear_benchmark` -- tests whether a nonlinear model (XGBoost,
  then LightGBM, then RandomForest, first available) extracts materially
  more signal from the same frozen feature set than the linear baseline.
